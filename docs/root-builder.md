# Explicit Root Builder lifecycle

This opt-in VR path supports the audited Root Builder5.1.1 copy package only.
It is a candidate until Polygon qualifies this exact executor, installation,
configuration and restoration. It does not change the plugin or install SKSEVR.
Third-party sources and binaries remain external; obtain Root Builder from the
dependency recipe rather than copying it into this repository.

The configured registered `SKSE` entry must target `game/sksevr_loader.exe`,
with the game working directory and no arguments. A missing deployed loader is
allowed only when the enabled, unique winning source mod contains the pinned
three-file SKSEVR bundle. MO2 autobuild performs the deployment.

The explicit configuration fields are:

```json
{
  "root_builder_data": "C:/MO2/plugins/data/RootBuilder/<exact-game-key>/1_4_15_0",
  "root_builder": {
    "mode": "copy-5.1.1",
    "pluginTreeSha256": "b1c2ae18837b625016a125d7e8897d6f7b73016bef6d64ddd398c7643b898e9f",
    "loaderMod": "<actual enabled SKSEVR mod directory>",
    "bundleSha256": {
      "sksevr_loader.exe": "<actual lowercase SHA256>",
      "sksevr_1_4_15.dll": "<actual lowercase SHA256>",
      "sksevr_steam_loader.dll": "<actual lowercase SHA256>"
    }
  }
}
```

The example is incomplete and cannot launch. `root_builder_data` must be the
plugin's existing directory for the configured game/version, never a guessed
cache from another installation. Preflight verifies the installed plugin tree
(excluding generated bytecode), copy pattern `**`, no link/USVFS patterns,
autobuild/hash/backup/cache/migrated settings, exclusions, clean inactive
BuildData state and existing GameData/Backup. Changed package/settings/layouts
require a separate review; no default repair, re-cache or migration is attempted.

Only a newly owned MO2 is supported; `reuse_test_profile` must be false. An idle
configured MO2 may be gracefully restarted under the existing explicit restart
authorization. It is reopened after verified restoration. Bridge `/session`
binds the new manager's PID, native creation time/path, boot and instance. Launch
uses the Bridge's expected boot/instance/profile guards. Its retained process
handle supplies the exact loader identity even if the short-lived loader has
already exited; a PID guess cannot replace that receipt.

Before setup writes, the executor journals existing bytes and membership for
all Root source trees, overwrite/Root, the filtered game-root view and the exact
Root Builder data tree, plus the version manifest. This includes disabled Root
mods because plugin clear can synchronize game changes back into mod sources.
The two known OpenComposite mods are disabled in the copied SteamVR profile;
their sources remain snapshotted. Staged overwrite/Root winners are planned
before deployment. A mismatched or ambiguous SKSEVR winner is refused.

After launch, before common world readiness or subject actions, the actual
BuildData source map, copied profile and deployed three-file bundle are checked.
DevBench queue availability remains distinct from gameplay readiness.

Restoration first ends the exact owned game/loader/MO2 and rejects unknown live
owners. Generic staged outputs are restored before the managed Root scope. That
scope uses its own validated journal, individual file removal, empty-directory
removal and complete byte/membership comparison; no recursive deletion is used.
Directory-only inventory covers the vendor's empty-folder cleanup, including
excluded Data/Saves directories, without hashing every BSA. Restoration failures
keep the run un-restored and preserve the recovery barrier.

Unexpected mutable hardlinks or reparse points are refused. The sole admitted
read-only hardlink invariant is an already-writable, cached `SkyrimVR.exe` outside
every deploy/write/delete scope. It is never snapshotted or rewritten. Its bytes,
device/inode/link count, mode and attributes must remain identical. Missing,
recreated or changed identity yields `RootBuilderUncertainty`; the executor never
repairs a shared inode or silently claims restoration.

The full original failed qualification and accounting remain immutable. Fixing
this launch contract neither retries an old qualification ID nor clears an
uncertain reservation. Polygon must finish reconciliation and freeze a new
bounded qualification with the new source/configuration pins.
